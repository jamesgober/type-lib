# type-lib v1.1.0

Fixes from an independent review of 1.0.0, plus three small additions. No
breaking change for code that used the derive as documented. MSRV stays 1.75.
`type-lib` and `type-lib-derive` are both at 1.1.0.

## The derive keeps its promise

`#[derive(Validated)]` said the field stays private, but it accepted a `pub`
field. Any code could then write `Percent(150)` or `p.0 = -7` and skip `new`.
The derive now refuses a field that is not private:

```text
error: #[derive(Validated)] requires the field to be private: remove the
       visibility so that `new` is the only way to build the type and the
       invariant holds
 --> src/lib.rs:5:20
  |
5 | pub struct Percent(pub i32);
  |                    ^^^
```

Only types that were already open to unvalidated construction stop compiling.

## Deserializing a validated type

Deriving `Default` or `serde::Deserialize` next to `Validated` builds the struct
without calling `new`, and the old docs invited both. The derive now generates
`impl TryFrom<T>` through `new`, so one serde attribute routes every value
through the validator:

```rust
#[derive(Validated, Clone, serde::Serialize, serde::Deserialize)]
#[serde(try_from = "String", into = "String")]
#[valid(And<Trimmed, LenRange<3, 16>>)]
pub struct Username(String);

impl From<Username> for String {
    fn from(u: Username) -> String {
        u.into_inner()
    }
}
```

The docs list the derives that are safe next to `Validated` (`Debug`, `Clone`,
`Copy`, `PartialEq`, `Eq`, `PartialOrd`, `Ord`, `Hash`, `serde::Serialize`) and
warn about the rest.

## Other fixes

- `InRange<10, 0>` and `LenRange<16, 3>` now fail to build where they are used,
  instead of compiling into a type no value can inhabit.
- `#[valid(V, crate = path)]` lets the derive work through a renamed dependency
  or a suite re-export.
- Length rules stop counting once the answer is known. `MaxLen<16>` on a 64 MiB
  string is decided from the byte length.
- `Refined` and the derive document that `T` must not change through `&T`
  (`Cell`, `RefCell`, atomics, `Mutex`), since the rule is checked once.

## Additions

- `rules::Finite` (`f32`, `f64`): rejects NaN and infinity. Combine with a sign
  rule, as in `And<Finite, Positive>`.
- `rules::AsciiAlphanumeric`: ASCII letters and digits only, for identifiers.
  `Alphanumeric` stays Unicode and now says so next to its lookalike risk.
- `HasLength::length_at_most`: a provided method the length rules use to stop
  early. Existing impls need no change.

## Upgrading

```toml
type-lib = { version = "1.1.0", features = ["derive"] }
```

If a derived type no longer compiles, make its field private and build values
with `new` or `try_from`. If an `InRange` or `LenRange` no longer compiles, its
bounds were inverted and the type rejected every value.
